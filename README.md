# 港口船员登离轮身份核对与岸上通行系统

按**航次**管理船员登岸 / 返船，离港前由船长**逐人核对**实际应返船人员，不能只凭人数相同判定到齐。

技术栈：TypeScript · NestJS · React 18 + Vite · Prisma · SQLite。扫码为本地模拟。

## 一条命令启动

```bash
npm run install:all            # 首次：安装前后端依赖
npm run dev                    # 建库 + 播种示例数据 + 同时启动后端(3001)与前端(5173)
```

打开 http://localhost:5173

- 后端 API：http://localhost:3001/api
- 首次启动自动建库并播种示例航次「远洋号 V-2610」（4 人名单）
- 端到端验证（8 个场景、40 项断言，使用独立测试库，自动清理）：

```bash
npm run verify
```

## 页面

| 页面 | 功能 |
|---|---|
| 值守核对 / 离港 | 照片、证件尾号、在船/在岸状态；**未返船具体名单**；全员逐人到齐后船长才能确认离港；证件遗失暂停/恢复 |
| 代理名单 / 换班 | 提交航次名单；临时换班对同一航次提交**新版本**，旧版本自动替代、历史可查 |
| 船梯口扫码 | 模拟核验证件并扫码登记登岸/返船；在线/离线切换；离线事件入本地队列后补传；重复扫码演示 |
| 记录查询 | 通行事件按航次/证件/方向/来源过滤；名单版本变更记录 |

## 核心规则实现

- **逐人核对，不只看人数**：在船/在岸状态由「该人员在本航次的最后一次通行事件（按扫码时间 `scannedAt`）」推导：最后为登岸即在岸上。离港接口对当前生效版本名单逐人检查，缺一人即返回其姓名尾号并拒绝（409 `NOT_ALL_RETURNED`）。
- **换班权限不延续**：换班生成新 `ManifestVersion`，旧版 `superseded`；仍在岸上的被换人员写入 `RELIEVED` 交接事件，移出未返船名额。旧版人员换班后在线扫码返回 `NOT_ON_MANIFEST`；离线补传按「事件发生时刻的生效版本」校验，换班后发生的事件拒绝，换班前的历史事件保留。
- **证件遗失**：`Person.status = SUSPENDED`，船梯口在线扫码直接拒绝，直到恢复通行。
- **离线补传与去重**：事件以设备生成的 `eventId` 全局唯一（DB 唯一约束兜底）。补传时批次内重复、与库内重复（含整批重发）都计入 `duplicate` 而不会产生第二条记录，同一人不会被算两次返船。
- **晚返船不漏记**：补传事件一律按扫码发生时间落库并参与状态归并，乱序/晚到也能正确把人从岸上改为在船；不按当前状态拒绝历史事件。
- **离港锁定**：确认离港后航次 `DEPARTED`，扫码、离线补传、换班名单全部关闭。

## 数据模型（server/prisma/schema.prisma）

`Vessel 1—n Voyage 1—n ManifestVersion 1—n ManifestEntry n—1 Person`；`AccessEvent` 以 `eventId` 唯一，记录方向（登岸/返船/换班交接）、扫码时间、补传来源与批次。
